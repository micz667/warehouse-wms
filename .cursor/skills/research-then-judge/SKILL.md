# Research, then judge

A fan-out is spend the human authorizes. Never start this unprompted. One opinion is not research.

## Researchers

Spawn or run two independent reads. Prefer two models when the harness allows it. Each report reads only what the question names: a repository at a revision, a documentation URL. Fetch it. Do not search. Do not invent a source. Recalled API is not a source.

If the question names no source, say so and stop.

A report carries the verdict, the tradeoff that decides it, and the source that proves it. Quote or cite the fetched text. A claim without a fetched source is not a finding.

File each final message as `report-1.md`, `report-2.md`, … in the feature folder, or in `spec/research/<slug>/` when the question has no feature yet. Strip trailing whitespace. Commit those files before judging. Researchers do not write the files' names into their own reports as if filing were their job — the coordinator files.

## Judge

Read only the filed reports plus the sources they cite. Name where they diverged: the claim, the tradeoff, the source. Agreement is one line. Divergence is the body.

Do not pick a winner by blending. Do not average. If they disagree, keep the disagreement visible and write the input a spec needs — a ticket, a decision, or a vision paragraph — not a compromise that hides it.

First line of the judgment names the divergence in one clause, or says they did not diverge. File verbatim as `judgment.md` beside the reports.

## Do not

Edit the board, ticket status, or outcome files. Merge. Plan or reprioritize the wider project.
